## 1. What this project is

A **matching decompilation** of Tony Hawk's Underground 2 (USA, GameCube, game ID
`G2TE52`) using `decomp-toolkit` (dtk) + `dtk-template`. **THUG2's game code was
NOT compiled with Metrowerks mwcc — it was built with SN Systems ProDG
(`ngccc.exe`, a GCC 2.95.2 fork for GameCube).** The CRT/runtime objects still use
mwcc (GC/1.3.2 via wibo), but every game-code source must be compiled with ngccc
(the dtk build already supports this — see §4 row 6). The build produces a
`main.dol` whose SHA-1 is **byte-identical** to the original game's. Over time,
functions are re-written in C; each one is verified to compile to the exact original
bytes, so the binary stays identical until 100% of the game is readable source.

- Original DOL SHA-1: `ff6faeb0f2b524ecbe1aeaff78ff154a284c27c9`
- No RELs, no map file — a single 3.06 MiB `main.dol`. Simple.
- No leaked source — everything comes from the binary.

## 3. Build & verify (the commands that matter)

```sh
cd <repo>

# One-time / after wiping build/: regenerate everything (downloads compilers, slow first time)
# (first clone: fetch tools/dtk + tools/ninja as above — both are gitignored)
python3 configure.py --dtk tools/dtk --ninja tools/ninja

# Fast build of just the DOL (the default target is "progress" — see §6 gotcha)
tools/ninja build/G2TE52/main.dol

# Run the hash check ("build/G2TE52/main.dol: OK" means matching)
tools/ninja build/G2TE52/ok

# Manual byte-verification
cmp orig/G2TE52/sys/main.dol build/G2TE52/main.dol   # must be identical
sha1sum build/G2TE52/main.dol                        # ff6faeb0...

# Full build incl. objdiff report (slow, minutes) — only when wanted
tools/ninja
```

The `elf2dol` ninja rule runs `tools/patch_dol.py` on the output automatically.
A **from-scratch rebuild** has been verified to produce the identical hash:
`tools/cold_rebuild.sh` preserves `build/compilers` (avoids re-downloading the
several-hundred-MB toolchain), wipes the rest of `build/`, reconfigures with
`--compilers`, rebuilds, and runs the hash + `cmp` check. Run it after any
change to `project.py`/`configure.py` to prove the build still works cold.

Note: `tools/project.py` COMPILER_MAP maps `ProDG/3.9.3` to decomp.me's
`prodg_393` (verified against upstream compilers.py), so ProDG units get
scratch metadata in objdiff.json. `scratch_preset_id` stays `None` — no
THUG2 preset exists on decomp.me.

## 4. The five customizations that make it match (do not "fix" these)

The stock dtk-template does NOT match this game out of the box. See the plan §4 for
the full story; the operational summary:

| # | What | Where |
|---|---|---|
| 1 | `skip_cfa_ranges` for Neversoft jump-table stall (overlapping fn @ 0x8025B92C) | `config/G2TE52/config.yml` |
| 2 | Second `.rodata` renamed to `.rodata2` (dtk: "Multiple sections with name") | `config/G2TE52/splits.txt` + symbol relabels |
| 3 | `__start` label on DOL entry 0x80003100 (mwld default entry) | `config/G2TE52/symbols.txt` |
| 4 | Custom LCF pins `_stack_end = 0x803CAF80` (tracker mis-attribution) | `config/G2TE52/ldscript.tpl` + `ldscript_template` key in config.yml |
| 5 | **SDA fix**: original compiled with `-sdata2 0`, so ALL small data is r13-addressed; dtk classifies sec 11 as `.sdata2` → mwld emits r2 accesses. Post-link patch rewrites r2→r13 (+0xD00 disp) and fixes init r2 (0x803D2F80→0x803E2280). | `tools/patch_dol.py` (constants at top are game-specific) |
| 6 | **ProDG ngccc build rule**: game code is GCC (not mwcc). Objects whose `mw_version` starts with `ProDG/` compile via a new `ngccc` ninja rule: `SN_NGC_PATH=<compilers>/ProDG/x.y`, `-MD` depfile (GCC format), then `powerpc-eabi-objcopy -R .sdata -R .sdata2 -R .sbss -R .sbss2` (mwld's LCF has no `.sbss2` and rejects it; GCC always emits those sections, empty here). | `tools/project.py` (`generate_build_ninja`), `configure.py` (`cflags_game` + `"mw_version": "ProDG/3.7"`) |

## 4b. Compiler (the lines that matter before touching flags)

- Game code = SN Systems ProDG `ngccc.exe` (GCC 2.95.2 fork), project on
  **`ProDG/3.9.3`**. CRT/runtime objects = mwcc GC/1.3.2 via wibo.
- Base game flags: `-O2 -G0 -mcpu=750 -fno-common` (`-G0` is load-bearing:
  plain `@ha/@l` globals, no small-data). History/details: recipes §4b.
- `-mps-float` is **per-object only** (`Object(..., extra_cflags=["-mps-float"])`
  via the `// extra_cflags:` marker) — globally it breaks FPR-frame matches.
- Stay in **C** (`.c` → unmangled symbols; C reproduces the game's codegen,
  including vtable calls). Virtual calls are `mtlr`+`blrl` via an fn-pointer
  cast — never `mtctr`/`bctrl`. `.cpp`/C++ only per-function if ever needed.
- Store order in source matters (ngccc emits stores ~reverse source order);
  ascending-address statement order is the usual seed. Details: recipes §§4p/24/64.
- SDK is Dolphin `0x2301`; `libs/dolphin/` is a newer superset — read
  `docs/dolphin-sdk.md` before wiring/adapting any SDK module.
- Functions whose returns are only 0/1 use `bool` + `return true/false;`
  (byte-identical: `bool` is `typedef int`); mwcc-region files keep integer
  returns since mwcc C has no `bool` type.

## 5. Core workflow (sweep → promote)

Drafts in `src/wip/` are **inert** (unregistered → never compiled → DOL stays
byte-identical). Never write ASM_FUNC stubs (asm-in-C fakes the objdiff match).

```sh
tools/venv/bin/python tools/test_wip_drafts.py --addr 0x8003F6F0  # or --slice i/8; full: bash tools/sweep3.sh
tools/venv/bin/python tools/promote_wip.py 0x8003F6F0 ...         # pass addrs explicitly; re-verifies + rebuilds + cmp
```

- Sweep honours each draft's own `// FLAG:` / `// extra_cflags:` lines and
  auto-adds `-mps-float` for `__ps_t` bodies. Keep the `// family=` marker
  intact (dropping it scores the draft flagless). Verdicts: EXACT (promotable),
  NEAR (>50%), DIFF, FAIL.
- If the sweep tags EXACT `[dummy]`, write `volatile double _dummy;` into the
  draft FIRST (the verdict came from an injected dummy). N dummies ≈
  (want_frame − native_frame)/8; prefer frame-struct pads for fine sizing.
- Promotion requires the `// range=0xS-0xE size=N` marker to match
  `config/G2TE52/symbols.txt` exactly (else the split overlaps the next unit
  and the link diverges). `tools/check_markers.py` scans for this.
- Promotion refuses (and the sweep skips) drafts whose address is already
  matched in the build — libs/ units (runtime/dolphin/...) or named game
  units (vcall_*, ...). Never hand-copy such a source into `src/fn_*.c`:
  the twin is never compiled and rots (Oct-2026 cleanup removed 12).
- Before believing any 100%: object `.text` size must equal the symbol size,
  no private `.rodata` (doc-14 pool caveat) unless routed, asm share small
  (whole-body transcription is banned regardless of verdict), and masked-EXACT
  hides branch targets/addresses — verify REL14/REL24 + decode `lis`/`addi`
  pairs by hand (recipes §§6bw/277/283).
- NEAR triage order: **semantics first** (callee arity/return-type audit from
  the callee prologue + call-site registers, field-pass vs literal, chained
  r3, `lbl_` symbol vs literal, struct member types) — most "scheduling"
  parks were wrong protos or mis-decodes. Flags/pins/barriers last, and
  re-measure stale scaffolding (`// FLAG:`, pins, barriers, `_dummy`) on the
  fixed body — it often flips from load-bearing to harmful.
- Regenerate progress after matches (needs rebuilt objdiff-cli after a cold
  rebuild: `tools/ninja build/tools/objdiff-cli` first):
  `build/tools/objdiff-cli report generate -o build/G2TE52/report.json && tools/venv/bin/python tools/gen_progress.py`

## 6. Tools (daily drivers + hygiene)

Daily drivers: `test_wip_drafts.py`, `promote_wip.py` (+ `sweep3.sh` /
`promote3.sh`), `want_got.py` (`--file` for variants; in-process recipe-279
dumper), `ps_diff.py`/`ps_disasm.py` (PS; plain disasm stalls on PS words),
`flagdiff.py`, `sda_verify.py`/`mwcc_verify.py` (sdata/mwcc zones),
`gen_leaves.py`/`add_gen_leaves.py`, `fill_wip_drafts.py`, `disasm.py`,
`cmp_dols.py`, `gen_progress.py`, `fix_fp_pool.py`. Full table: recipes §5.

**Hygiene (non-negotiable):** `tools/` stays curated + documented. One-off
probes, single-address experiments, throwaway verify/commit scripts, superseded
scanners, and round-local logs/dumps go in **`/tmp/`** (namespace per
batch: `/tmp/opencode/<batch>_...`) — never in `tools/` or the repo root, and
never `git add -A` while a probe exists. Promote to `tools/` + document only
what earns it twice. Score variants with a private `LEAF_TMPDIR`
(`export LEAF_TMPDIR=/tmp/opencode/<yours>`); the default `/tmp/leaf` is
shared and races concurrent agents. Cleanup backstop: `tools/cleanup_oneoffs.sh`.
Never mention your harness, session, or agent identity in code comments, commit
messages, or docs — write as the project. A comment should explain the code
for the next reader, not who or what wrote it. Concretely: comments (especially
`src/wip/` draft headers) must describe ONLY the current state of the file —
status, scores, walls, levers tried and their results. Dates are fine, but never
authorship or batch/session provenance (`PARKED 2026-10-13 (random batch):`,
`RE-TRIAGE <date> (<batch>):`, `(agent w9)`, ...): the batch a note came from
is never actionable. No history narratives about fixed past problems either —
once fixed, say nothing (the current state already shows it).
Write `// PARKED 2026-10-13: 73.3%, prologue-through-vcall exact; residual
is ...`, not `// PARKED 2026-10-13 (random batch): ...`. Never reference `/tmp/` paths
in committed code, comments, or docs either — `/tmp` is wiped, so such a path
is a dead reference to the next reader; preserve anything worth keeping under
`tools/reference/` instead.

**No assembly dumps in comments (README policy):** README states the repo
contains no game assets or assembly whatsoever. Never commit comments that
reproduce original disassembly — no multi-line instruction listings (`//   lis
r...`, `//   lwz r...`, ...), no `Original disassembly (range...)` blocks, no
WANT/GOT instruction tables. Describe behavior and structure in prose instead
(function shape, frame size, struct offsets, blockers, scores). A lone
mnemonic is acceptable only when load-bearing to explain codegen (e.g. why a
local forces constant placement) — never a listing. The `gen_wip_drafts.py`
stub fallback stays a bare stub (address/size marker only, no disassembly).

## 7. Environment quirks (sandbox-specific)

- venv: `ensurepip` broken on Python 3.14 (bootstrapped via get-pip). Use
  `tools/venv/bin/python` for m2c/capstone; `configure.py` runs on `python3`.
- No sudo/dnf/pip3; `flatpak --user` installs fail (only needed for Dolphin boot tests).
- **`tools/ninja` default target is `progress`** (minutes). Always build
  specific targets (`tools/ninja build/G2TE52/main.dol`, `.../ok`).
- First build downloads compilers into `build/compilers` (hundreds of MB).
  After `project.py`/`configure.py` changes prove cold builds:
  `tools/cold_rebuild.sh` (preserves compilers) or `tools/final_verify.sh`.
- **Killed ninja corrupts `.ninja_log`/`.ninja_deps` (repo root) → next build
  loops forever** (`premature end of file`, `[2/N]` counter keeps climbing,
  ~0 CPU). Fix: `rm -f .ninja_log .ninja_deps` (+ `build/.ninja_log`) and
  rebuild. Never leave long builds attached to a call that can time out —
  log to a file and poll from short calls.
